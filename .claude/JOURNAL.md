2. **Task - Hybrid shell-less terminal launch** (v0.6.4): Implemented the core capability - generic `basic-terminal:launch` JL command spawning a JupyterLab terminal whose pty's only process is a caller-supplied `argv`, with auto-focus on launch and auto-close on exit<br>
   **Result**: Replaced the scaffold `HelloRouteHandler` in `jupyterlab_basic_terminal_extension/routes.py` with `LaunchTerminalHandler` (`POST /launch-terminal`), modelled on `jupyterlab_claude_code_extension/routes.py:198-253`. Backend validates `argv` as a non-empty list of non-empty strings and optional `cwd` as an existing directory, then calls `terminal_manager.create(shell_command=argv, cwd=cwd)` - terminado's per-call `shell_command` kwarg replaces the user's `$SHELL` so the pty has no surrounding bash. Returns `{terminal_name}` handling both dict-like and object-like model returns. Rewrote `src/index.ts` to register the JL command (programmatic-only, no menu/palette helper) accepting `{argv, cwd?}`, POSTing to the backend, attaching the standard JL widget via `terminal:open`, focusing it via `app.shell.activateById`, and disposing the widget on `session.disposed` or `connectionStatusChanged === 'disconnected'` so the tab closes the moment the underlying process exits. Added parametrized `test_routes.py` covering invalid_json/argv/cwd plus happy-path with and without cwd. Bumped `package.json` to `0.6.4` per explicit request. No new npm/python deps; `Makefile` already at canonical v1.31.

3. **Task - Terminal-init wait, CI hardening, first PyPI release** (v1.0.3): Server-side init waiter so TUI tools see a real pty size at launch; fixed metadata that crashed PyPI; tightened CI<br>

Eliminates per-caller init loops like `/opt/utils/launch-lab-utils.sh`. Tracking `package-lock.json` + `yarn.lock`. Added as workspace submodule.
