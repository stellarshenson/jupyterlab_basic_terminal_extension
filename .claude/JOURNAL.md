5. **Task - Real pty resize wait, 1.0.6 release** (v1.0.6): Fixed `_INIT_WAITER` in `routes.py` so spawned utilities see the JL terminal tab's actual width on first paint, not terminado's 24x80 default<br>
   **Result**: Previous waiter polled `stty size` for `r >= 20 && c >= 80` - terminado's default 24x80 trivially passed iteration 1, the loop never waited, and TUI clients (claude, htop, dialog) painted their initial frame at 80 cols inside a wider tab. Most TUIs do not repaint on the WebSocket-triggered resize, so users were stuck looking at a narrow window. New waiter captures the initial size with `stty size`, installs a `trap 'CHANGED=1' WINCH`, and breaks on either signal or a polled size diff. After `exec "$@"` bash is replaced by the target on the same pid so auto-close on exit still works; 5 s timeout still fires when no client connects (headless tests). Same fix as the peer `jupyterlab_claude_code_extension` v1.0.46. Released 1.0.6 via `make publish`; deleted the resolved `TODO_PTY_RESIZE_WAITER.md`.

6. **Task - Adversarial review triage and scoped fixes** (v1.0.6): Ran an architect + bug-hunter panel over the cwd change set, triaged both lenses against the live tree, fixed the confirmed findings<br>
   **Result**: Bug-hunter found a CRITICAL, confirmed against the installed bundle: `terminal:open` delegates a name it cannot find to `terminal:create-new`, whose `startNew({name})` branch spawns the user's `$SHELL` - no argv, no cwd, no auto-close, the exact guarantee this extension exists to make. Terminado frees the name on EOF, so any pty exiting before the widget mounts armed it, and the 5s `_INIT_WAITER` cap was shorter than a cold-start round-trip. Closed both ways - `_INIT_WAIT_POLLS = 300` widens the wait to 30s, and `src/index.ts` refreshes the running list and throws if the name vanished. Also routed the browser path through `contents.localPath()`, since a `Drive:` prefix previously 400d every no-cwd launch; named `_INIT_SHELL`; documented the command id in README, it being the whole public surface. Declined two MAJORs - the disposal gap needs a new `@jupyterlab/terminal` dependency, the dual package-manager one contradicts the project's `package-lock.json` rule. 15 pytest, 7 jest, tsc and prettier clean.

7. **Task [Extended] - Re-confirm round fixes three self-inflicted regressions** (v1.0.6): Round 2 of the adversarial panel returned DO-NOT-SHIP against the round-1 fixes themselves; all four findings reproduced and fixed<br>
   **Result**: The launch guard read `terminals.refreshRunning()`, a `@lumino/polling` refresh that dedups concurrent refreshes and swallows errors - two launches close together shared one pre-launch snapshot, so the second was rejected as "exited" while its pty leaked invisibly, the command rejecting into a floating promise nobody subscribes to. Swapped for `TerminalAPI.listRunning()`. Widening `_INIT_WAIT_POLLS` to 300 was the wrong remedy: the budget doubles as a blank-screen stall whenever no resize arrives, and terminado skips `setwinsize` when the client size equals the pty's, so a panel fitting exactly 24x80 stalled the full 33.5s - as did every bad `argv[0]`. Replaced the number with a mechanism: `stty rows 1 cols 1` before arming the trap guarantees any real client differs, ending the wait on attach (0.32s, from 33.5s), restoring 24x80 if the backstop wins. Third regression: `contents.localPath()` silently stripped a registered drive prefix, so `S3:data/raw` resolved against the local root and launched in an unrelated directory that previously 400d - now gated on `driveName()`. 17 pytest, 8 jest; three waiter mutants each killed by one test.

8. **Task - Round 3 confirms fixes, corrects an overclaim** (v1.0.6): Bug-hunter returned SHIP on runtime evidence; architect found the drive gate's stated rationale false, corrected by deletion<br>
   **Result**: `ContentsManager.driveName()` returns non-empty only for a prefix in `_additionalDrives` - it tests *registered*, not *remote* - and `Drive` defaults `apiEndpoint` to `api/contents` without ever sending the drive name, so a drive registered with no endpoint override reads the same `root_dir`. The `src/index.ts` comment ("only the default drive is backed by the server filesystem") and the README bullet ("a remote drive path has no local directory") were false as general rules; both now say a registered drive is not *assumed* to map onto it. Deletion only, no behaviour change. Bug-hunter cleared all three round-2 fixes on a real pty and in chromium - the exact-24x80 stall drops 7.85s to 0.42s - and disproved its own regression hypothesis by measuring the wire: JupyterLab sends `set_size` twice, both already fitted. `graphify` puts the blast radius at exactly the diff.
